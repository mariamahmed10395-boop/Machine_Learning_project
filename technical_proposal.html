1. Executive Summary

The CharityML Finding Donors Predictor is a supervised machine learning project that predicts whether an individual earns more than $50,000 per year using U.S. Census data. The goal is to help a fictitious charity organization — CharityML — identify the most likely donors and optimize outreach efforts.

The system currently features a modular Python codebase, three custom-built classifiers (Random Forest, Logistic Regression, Gradient Boosting), and a Tkinter desktop GUI for interactive predictions. The project goes beyond the base Udacity template by adding a desktop application with real-time feature adjustment and model comparison capabilities.

This proposal outlines the current state of the project, identifies technical gaps and areas for improvement, and presents a 5-phase roadmap for elevating the project to production quality — including real data integration, scikit-learn model upgrades, MLflow experiment tracking, GUI modernization, and automated testing.

3. Technical Analysis & Identified Gaps

3.1 Data Pipeline

⚠️ Warning: GUI uses synthetic data only
The GUI currently generates random synthetic data instead of loading the real census.csv dataset. The "Browse" button exists but ultimately calls the same synthetic data generator regardless of file selection.

The data_utils.py module generates random data with a hardcoded label-scoring heuristic, rather than loading the real UCI Census dataset. The actual census.csv file (5.4 MB, ~32,561 records) is present in the directory but is never read by the GUI application.

3.2 Machine Learning Models

ℹ️ Important: All classifiers are simplified custom implementations
None of the three models use scikit-learn. They are hand-coded approximations with significant limitations.
Model Implementation Limitation
SimpleRandomForest Bagged decision stumps (single-feature, single-split) Not real decision trees; each tree uses only 1 random feature and 1 split threshold
SimpleLogisticRegression Vanilla gradient descent No regularization (L1/L2), no convergence checking, fixed learning schedule
SimpleGradientBoosting Sequential single-stump boosting Same single-feature/single-split limitation; O(n) residual update loop per tree

Reported accuracy (from README):

Model Accuracy
Logistic Regression 71.87%
Random Forest 64.40%
Gradient Boosting 72.01%

3.3 MLflow Integration

📝 Note: MLflow is mentioned but not implemented
The README states "Integrated MLflow for experiment tracking, metric logging, and model versioning" — however, no MLflow code exists in any source file. There is no import mlflow, no experiment tracking, no model registry, and no artifact logging.

4. Proposed Improvement Roadmap

The improvement plan is organized into 5 sequential phases, ordered by priority and dependency. Each phase builds upon the previous one.

1
Real Data Pipeline
~2 days

Goal: Replace synthetic data generation with real census.csv loading and proper preprocessing.

  • MODIFY data_utils.py — Add load_census_data(filepath) function using pandas.read_csv()
  • Implement proper one-hot encoding for categorical features (or ordinal encoding for tree-based models)
  • Add log-transform for skewed features (capital-gain, capital-loss)
  • Implement train/test split with stratified sampling
  • Keep generate_synthetic_data() as a fallback for demo mode
  • MODIFY app_gui.py — Wire up "Browse" button to actually load and validate CSV files
  • NEW requirements.txt — Pin all dependencies for reproducibility
2
Production-Grade ML Models
~3 days

Goal: Replace simplified custom classifiers with scikit-learn implementations for production-quality accuracy.

  • MODIFY models.py — Replace custom implementations with scikit-learn:
  • SimpleRandomForest → sklearn.ensemble.RandomForestClassifier
    SimpleLogisticRegression → sklearn.linear_model.LogisticRegression
    SimpleGradientBoosting → sklearn.ensemble.GradientBoostingClassifier
  • Create a ModelWrapper class for unified API across all models
  • Add GridSearchCV hyperparameter optimization for best model
  • Add model serialization with joblib.dump/joblib.load

Expected accuracy improvements:

Model Current (Synthetic) Expected (Real + sklearn)
Logistic Regression 71.87% ~82–84%
Random Forest 64.40% ~84–86%
Gradient Boosting 72.01% ~86–87%
3
MLflow Experiment Tracking
~2 days

Goal: Implement the MLflow integration referenced in the README.

  • NEW mlflow_utils.py — Create MLflowTracker class for experiment lifecycle management
  • Log hyperparameters, metrics (accuracy, F₀.₅, precision, recall), and confusion matrices
  • Log feature importance plots as MLflow artifacts
  • Register best models in MLflow Model Registry
  • Provide local MLflow UI launcher (mlflow ui --port 5000)
  • MODIFY app_gui.py — Add "Track with MLflow" toggle and "Open MLflow UI" button
4
GUI Modernization & Decomposition
~3 days

Goal: Further decompose the monolithic 961-line GUI class into reusable components.

  • NEW gui/__init__.py — Package initialization
  • NEW gui/panels/left_panel.py — Dataset & model configuration panel
  • NEW gui/panels/center_panel.py — Feature input panel
  • NEW gui/panels/right_panel.py — Results & visualization panel
  • NEW gui/components/chart_widget.py — Reusable chart component
  • Add loading spinner/animation during model training
  • Add export functionality (save predictions to CSV, export charts as PNG)
  • MODIFY visuals.py — Remove IPython dependency; make compatible with standalone Python
5
Testing & Deployment
~2 days

Goal: Add automated testing, CI configuration, and project packaging.

  • NEW tests/test_data_utils.py — Data loading, preprocessing, and metrics tests
  • NEW tests/test_models.py — Model training/prediction tests with small datasets
  • NEW .gitignore — Exclude __pycache__, .venv, mlruns/
  • NEW pyproject.toml — Package configuration with pip-installable entry point
  • Translate Arabic comments to English for international accessibility

5. Risk Assessment

Risk Likelihood Impact Mitigation Strategy
scikit-learn version incompatibility Low Medium Pin exact versions in requirements.txt
MLflow server resource usage Medium Low Use local file-based tracking (no remote server)
GUI font unavailability on target systems Medium Low Add fallback font stacks in style configuration
census.csv format changes or corruption Low Medium Add schema validation in data loader with clear error messages
Training time increase with real sklearn models Low Medium Keep threaded training; add progress callbacks and timeout handling
